# shadcn-vue UI conversion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the browser client's interactive primitives (button, input, label, badge) onto shadcn-vue components while preserving the approved flight-recorder design, and make the generated shadcn surface untouchable (top-level note + Biome skips).

**Architecture:** Safety first — protect the generated surface BEFORE the CLI writes into it (Biome overrides + top-level CLAUDE.md), then `shadcn-vue add` the four primitives, then remap shadcn's semantic CSS variables onto the cc-web tokens in `tokens.css` (our file, later in the cascade), then convert the four call sites. Data display (journal rows, run separators, rail layout, stage header) stays hand-built — it is the design, not a primitive.

**Tech Stack:** shadcn-vue 2.8.2 (reka-vega style, reka-ui), Tailwind CSS v4, Vue 3.5 SFC scoped styles (unlayered → beat layered Tailwind utilities), Biome 2.6.2 overrides.

**Spec:** User request 2026-10-24: "Đổi giao diện sang sử dụng component đến từ shadcn vue và thêm 1 note cấp cao nhất 'Không bao giờ sửa/lint,... các file sinh ra của shadcn-vue'". Design spec: flight-recorder pass (tokens paper/ink/pine/amber, Instrument Sans / IBM Plex Mono), recorded in `.superpowers/sdd/2026-10-24-browser-client/progress.md`.

## Global Constraints

- **Never hand-edit, reformat, or lint-fix generated shadcn-vue files.** Regenerate via the shadcn-vue CLI instead; override at the call site. Generated surface: `apps/web/src/components/ui/**`, `apps/web/src/lib/utils.ts`, `apps/web/src/styles/index.css`, `apps/web/components.json`.
- The visible palette stays the approved cc-web tokens (pine #106b57, paper #fafaf7, ink #1a211e, amber #9a6700) — the preset's red must not leak into rendered UI. Remap happens ONLY in `apps/web/src/styles/tokens.css` (ours), never in generated `index.css`.
- No version pinning: caret ranges, `bun.lock` is the source of truth.
- Design continuity beats component purity: where a scoped class and a Tailwind utility conflict, the scoped style (unlayered) wins by CSS cascade — that is the mechanism, not a bug.
- Security invariants (§19.4) untouched: this work touches no auth, transport, or storage code.

**Testing deviation (recorded):** `bun test` cannot compile `.vue` SFCs, so component conversions carry no unit tests. This task introduces no new pure logic (the ConnectionChip computeds stay inside the component). Verification is typecheck + `bun test` (399 stay green) + `vite build` + a browser visual pass. Recorded as a deferred minor (vitest) in the ledger.

## Review Focus

1. **shadcn Input v-model must actually fill** — if `v-model` on the shadcn Input did not bind, login would silently break (button stays disabled). The browser pass must type a real value and see the button enable.
2. **Red preset leak** — after remap, the login button, focus ring, hover wash, and badge accents must be pine/amber, not the preset's red oklch. Visual pass checks exactly this.
3. **Generated-file protection gaps** — `bun run lint` must skip `components/ui/**` even AFTER Task 2 creates the files; a violation here means the override includes are wrong (path prefix, glob shape).
4. **Scoped-style regressions from Button's utilities** — session rows keep `.session-row` layout (padding, baseline alignment, inset active bar); Button's `h-9 px-4 text-sm` must lose every conflict. Visual pass checks row height/alignment.
5. **Disabled-state honesty** — the Composer's Input stays disabled with the honest placeholder; `aria-disabled` wrapper remains.

### Task 4: Convert the call sites

**Files:**
- Modify: `apps/web/src/views/LoginView.vue`, `apps/web/src/components/Composer.vue`, `apps/web/src/components/ConnectionChip.vue`, `apps/web/src/components/SessionRail.vue`

**Interfaces:**
- Consumes: `Button`/`Input`/`Label`/`Badge` from Task 2; semantic variables from Task 3.
- Produces: nothing downstream.

Conversion contract (design continuity rules):
- **LoginView**: `Label` + `Input` + `Button`. `v-model` binds directly on `Input`; `Button` keeps `:disabled="busy || username === '' || password === ''"` and `type="submit"`. Scoped styles for input focus/padding are DELETED where the component now owns them (the remapped `--ring`/`--primary` provide the focus look); the wordmark, lede, error copy, and grid layout stay.
- **Composer**: `Input` `disabled` with placeholder "Sending prompts arrives with the dispatch API — not wired yet.", inside the existing `aria-disabled` footer wrapper.
- **ConnectionChip**: the strip (border-top, margins) stays a plain scoped div; the status readout becomes `<Badge variant="outline">` carrying the dot + mono label; tone classes (`pine`/`amber`/`mute`) move to the Badge.
- **SessionRail**: session rows become `<Button variant="ghost">` keeping the existing `.session-row` scoped class (unlayered styles win every conflict → layout identical; Button contributes focus-visible rings). Row internals unchanged.
