## Goal

The next live demo must show M1 (markdown prose) and M2 (tool input summaries)
in the real UI, with the composer's project select fed by the fake runner's
workspace declaration. Two small drift/hygiene items ride along: a shared
`MODEL_IDS` constant (route + composer currently duplicate the list) and
`occurredAt` tooltips on streaming/tool rows (event rows already have them).

## Rulings (brainstorm folded in)

- **MODEL_IDS lives in `@cc-web/protocol`** — the only package both the
  control server and the web app already import. Export
  `MODEL_IDS = ["sonnet", "opus", "haiku"] as const` (§8.1 fixes these names)
  and `type ModelId`. The composer's label map becomes
  `Record<ModelId, string>` spread after `"default"` — adding a model id
  without a label is then a type error, which is the real drift protection;
  the route builds its validation set from the same constant.
- **Tooltips via `lastOccurredAt` on the derived row** — streaming/tool rows
  no longer hold the event object, so the derivation carries the `occurredAt`
  of the event that last touched the entry (the same event that sets
  `lastSequence`). The template binds `:title` on the sequence gutter, same as
  event rows. No new event types, no persistence change.
- **Fake runner changes are local-only** (`/tmp/cc-web-fake-runner.ts`, never
  committed): hello + reconcile both carry
  `workspaces: [{ workspaceId: "default", path: "/tmp/cc-web-demo-ws" }]`
  (reconcile without the field WIPES the hello declaration — §15.1), and the
  default run script becomes realistic: markdown deltas, a tool call whose
  `message.completed` carries a `tool_use` block with input, `tool.completed`
  with an output summary. The approve/question/block flows stay as they are.
- **Live demo pass on the existing stack** — control server :8787, vite :5173,
  demo login `ngotuananh2101 / 123@123a`; old journals replay through the new
  derivation (replay fidelity is itself worth eyeballing).
