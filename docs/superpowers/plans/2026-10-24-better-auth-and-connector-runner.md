# Better-Auth Web Login + Cloudflared-Style Runner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hand-rolled JWT login with better-auth (username/password, server-rendered sessions), and replace the one-time enrollment exchange with a cloudflared-style connector: the web mints a UUID token, the runner ships as one compiled executable that connects with it and can install itself as a systemd service.

**Architecture:** The Control Server mounts `betterAuth.handler` on `/api/auth/*` over the same bun:sqlite database (kysely `BunSqliteDialect`); every former `AuthService.authenticate` call site becomes `auth.api.getSession({ headers })`. Enrollment redemption disappears: `POST /api/runners` mints `{runnerId, token}` (token = random UUID, only its SHA-256 stored) shown once in the browser; the runner CLI gains `setup` (writes `identity.json` 0600, no server round-trip), `connect` (the old `run`), and `service install/uninstall/print` (systemd unit generated by pure, testable code). `bun build --compile` produces the single-file executable.

**Tech Stack:** better-auth 1.7.x (+ `username` plugin, `better-auth/vue` client), kysely-bun-sqlite, bun:sqlite, systemd unit files, `bun build --compile`.

**Spec:** docs/ARCHITECTURE.md v2.0 (§6 rewritten by Task 9; §19.4 invariants apply verbatim throughout).

## Global Constraints

- Never edit/lint/format generated shadcn-vue files: `apps/web/src/components/ui/**`, `apps/web/src/lib/utils.ts`, `apps/web/src/styles/index.css`, `apps/web/components.json`; the biome override protecting them stays LAST in the overrides array.
- §19.4 verbatim, still binding: provider token never reaches server/browser/journal/log; identity files 0600; only hashes of runner tokens stored; credentials travel in a header, never a URL; tokens are read from stdin/env/file, never argv; Origin allowlist before the browser WS upgrade; unknown/revoked tokens answer indistinguishably; credential responses carry `Cache-Control: no-store`; never log the token or command payloads.
- No version pinning: caret ranges only; bun.lock is the source of truth.
- Comments in code explain constraints (the "why"), matching the existing file voice; no narration comments.
- Theme tokens: only the generated semantic vars (`--primary`, `--border`, …) in app code; Inter stays self-hosted via `@fontsource-variable/inter`; never re-add a Google Fonts import.
- Real web build = `cd apps/web && bun run build` (never `bun --cwd`).
- Tests: `bun test`; full gate order = `bun run lint` → `bun run typecheck` → `bun test` → `bun run test:integration` → real web build.

## Review Focus

1. **Better-auth cookie through the vite proxy**: dev runs on :5173 with `/api` proxied to :8787; the session cookie must survive (SameSite=Lax, path=/) or the router guard 401-loops. Pinned by Task 4 e2e test (fetch through server with cookie jar) + Task 10 browser pass.
2. **Sign-out must close live browser sockets** (the old `tokenVersion` bump did this). Pinned by Task 4: databaseHooks.session.delete → gateway.revoke test.
3. **The minted token must not leak into logs or a second response** (no-oracle/no-store, §19.4). Pinned by Task 5: list route never returns a token; mint response is no-store; token appears exactly once.
4. **A revoked runner's token must stop working on the next connect** (not next restart). Pinned by Task 5 (revoke → verify fails) — the WS path already routes through `verifyRunnerCredential`.
5. **`service install` must never put the token in the unit file or argv** (§19.4: world-readable `ps`, unit files are 0644). Pinned by Task 6: unit file content test asserts ExecStart has no token and identity stays in the 0600 config file.
